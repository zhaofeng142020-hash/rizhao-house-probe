# 日照房价探针 · 捡漏雷达

> 面向**日照市区自住购房者**的房价监测 + 捡漏预警系统。
> 核心不是"展示房价"，而是**主动帮你发现可捡漏房源，并且先告诉你它为什么便宜**。

**一句话原则：先把低价当嫌疑，再判断是否值得看。宁可漏报，不可把坑包装成漏。**

## 1. 它解决什么问题

普通房源网站只会按价格排序，便宜的房子为什么便宜、值不值得跑一趟，没人告诉你。本系统做八件事：

| 能力 | 说明 |
|---|---|
| **价格异动监测** | 突发降价 / 连降 / 深跌 / 久挂让利，每日增量计算，产出「异动事件表」 |
| **可比低估判断** | 当前单价 vs 同小区同户型近 3 月中位，样本不足自动降置信度 |
| **坑 vs 漏的区分** | 每条候选强制输出「为什么便宜 / 为什么可能是真漏 / 为什么可能是坑」 |
| **法拍到手价折算** | 起拍价 + 税费 + 欠费 + 维修预留 = 到手价，再用到手价算净折扣 |
| **小区地图** | 一眼看清 15 个小区的方位、在售套数、中位单价；点一下进小区档案 |
| **小区维度聚合** | 一个小区所有在售房源列在一张表里，同户型竞争格局直接告诉你能砍多少 |
| **新房倒挂双口径** | 名义倒挂 + 「含装修、按得房率折算」的调整后倒挂，避免被建筑面积骗 |
| **购房成本与议价** | 一次性现金门槛、月供、租金视角、议价锚点（能谈到多少、从哪开始谈） |

监测板块：**新市区、东港区、石臼、老城、山海天、高新区、开发区**；
扩展区：**莒县、五莲、岚山**（单价更低但流动性明显更弱，评分里单独打折）。

## 2. 四种跑起来的方式

### 方式 A：在线访问（手机/电脑都能开，推荐先看效果）

**https://<你的部署域名>/?sharecode=<你的分享码>**

> 本仓库不含任何线上地址、分享码、管理口令、会话 Cookie 或运行数据。
> 请部署到自己的环境后，把上面的占位符换成你自己的访问链接。

- 手机浏览器直接打开，已做移动端适配：底部 5 个标签（今日 / 异动 / 地图 / 改善 / 更多抽屉，
  更多里放新房倒挂、观察清单、推送设置、管理台），指标卡两列、房源卡单列、表格改卡片列表、
  地图标签自动隐藏并放大点击区、刘海屏安全区留白
- 首次启动会灌一份演示样本便于看效果；接入真实数据源后不再覆盖，
  每天 07:30 / 19:30 自动刷新贝壳、安居客、58 同城三源。本地改完要更新线上，见下方「部署到线上」

### 方式 B：单文件演示版（零依赖，最快）

```bash
python standalone/demo.py
```

- 只用 Python 标准库，**不需要 pip install 任何东西**
- 自动打开浏览器 `http://127.0.0.1:8010`
- 内嵌 30 套示意挂牌 + 2 条法拍，含异动识别、捡漏评分、雷达图/箱线图/时间轴
- Windows 可直接双击 `run_standalone.bat`

> 前端依赖 CDN（Vue3 / Element Plus / ECharts），首次打开需要联网。

### 方式 C：标准工程 · Windows 本机直跑

**一键**：双击项目根目录的 `run_local.bat`（自动建虚拟环境 → 装依赖 → 构建前端 → 起服务）。

**手动**：

```bat
:: 1) 后端依赖
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

:: 2) 前端（可选：仓库已带构建产物时跳过）
cd frontend
npm install
npm run build
cd ..

:: 3) 配置（可选，先不配也能跑，推送自动降级为站内提醒）
copy .env.example .env

:: 4) 启动
python run.py
```

打开 <http://127.0.0.1:8000> ，接口文档 <http://127.0.0.1:8000/docs> 。

`run.py` 会监听 `0.0.0.0`，所以**同一 Wi-Fi 下手机也能用**：先 `ipconfig` 查本机 IPv4，
手机浏览器访问 `http://192.168.x.x:8000` 即可（Windows 防火墙需放行该端口）。

**首次启动会自动完成**：建表 → 检测空库并灌入演示数据 → 跑一次增量计算（打分 + 异动）→ 起定时任务（每日 02:30）。

**前端热更新开发模式**（前后端分离调试）：

```bash
# 终端 1：后端
cd backend && python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
# 终端 2：前端
cd frontend && npm run dev      # http://localhost:5173，/api 已代理到 8000
```

> `npm run build` 的产物直接输出到 `backend/app/webui`（不再用 `frontend/dist`），
> 由 FastAPI 单端口托管，部署时跟着 Python 包一起走。

### 方式 D：Docker

```bash
copy .env.example .env
docker compose up -d --build
# 访问 http://127.0.0.1:8000
```

镜像内已包含前端构建产物；`./data` 挂载为卷，重建容器不丢数据。

### 部署到线上（更新已发布的站点）

本地目录里有 `.venv`（约 200MB）和 `node_modules`，不适合直接上传。先打包成精简目录：

```bash
python deploy_pack.py          # 生成 ../rizhao-house-probe-deploy（约 3MB，65 个文件）
```

然后发布 `rizhao-house-probe-deploy` 目录即可；它含后端源码、已构建的前端产物、
`requirements.txt` 与 `run.py`，入口命令是 `python run.py`（读 `PORT` 环境变量、监听 `0.0.0.0`）。
改了源码重新跑一次 `deploy_pack.py` 再发布，链接不变。

云托管两点注意：

- 部署包里**不含 `data/`**，容器首次启动会建库 + 灌演示数据；重启即重新生成
- 容器每次重启会重新生成管理口令，所以云上请在环境变量里设 `ADMIN_TOKEN`（否则每次重启口令都变），
  本地自用则直接看 `data/admin_token.txt`

## 5. 数据库表设计

完整 DDL 见 [`backend/app/schema.sql`](backend/app/schema.sql)，共 16 张表：

| 表 | 作用 | 关键字段 |
|---|---|---|
| `community` | 小区基础盘 | 板块、建成年、电梯、对口学校、`lat`/`lng`（地图用）、`liquidity_score`、近 90 天成交 |
| `listing` | 二手房挂牌 | 去重指纹、单价/总价、`first_price`、`list_days`、`price_changes`、`consecutive_drops`、`defect_tags` |
| `price_history` | 调价向量 | 每次观测的价格、`drop_pct`、`days_gap` → 前端时间轴数据源 |
| `auction` | 法拍标的 | 评估价/起拍价/阶段、税费/欠费/维修预留、`landing_price`、`net_discount`、`risk_tags` |
| `new_home` | **在售新盘** | 均价、面积段、交付时间、装修标准、容积率、`lat`/`lng`、`risk_tags` |
| `anomaly_event` | **异动事件表** | `event_key` 日级去重、7 种 `event_type`、`severity`、指标明细 JSON |
| `leak_score` | **评分表** | 总分 + 5 个维度分 + 置信度 + 分级 + 三问解释文案 |
| `watch_item` | 观察清单 | 目标对象、跟进状态、`base_price`/`last_price`、备注 |
| `weekly_report` | 观察周报快照 | 每周「仍值得看 / 建议剔除 / 新可比低价」 |
| `alert_config` | 推送订阅配置 | 通道、最低分数、红黄开关、静默时段、去重窗口 |
| `alert_log` | 推送日志 | 同时承担**24h 去重**与**站内铃铛**数据源 |
| `crawl_log` | 抓取日志 | 单站成败、条数、耗时、错误（异常隔离的可观测性） |
| `app_setting` | **运行期配置** | `key`/`value`/`is_secret`，管理台保存即生效，不用重启 |
| `user_pref` | 用户偏好 | 板块/面积/户型/电梯/房龄/学区 + 首付比/贷款年限/利率/是否首套 |
| `community_price_snapshot` | **小区价格快照** | `(community_id, observed_date)` 唯一；中位/均价/极值单价、样本量、120-150㎡ 套数、`data_kind`（daily / backfill） |
| `source_import_batch` | **导入批次** | 每次真实导入的来源、收到/入库/跳过条数、备注，可逐批回溯 |

旧库升级时 `db.py` 的 `COLUMN_PATCHES` 会给 `listing` / `auction` / `new_home` 补
`source_kind` / `source_name` / `source_ref` / `collected_at`，给 `community` 补 `alias`。

设计要点：

- **去重指纹** = `md5(source + 小区 + 户型 + 面积取整 + 总价取整)`
- **调价追踪** 用「站点+小区+户型+面积」匹配同一套房源，价格变了追加 `price_history` 并累加 `price_changes` / `consecutive_drops`
- **单行配置** `alert_config` / `user_pref` 用 `CHECK (id = 1)` 保证只有一行
- **升级零迁移**：新表用 `CREATE TABLE IF NOT EXISTS`，新字段用 `ALTER TABLE ... ADD COLUMN`（已存在则跳过），
  旧的 `data/rizhao.db` 直接启动即可自动补齐，不会丢数据
- 所有金额单位 **元**，面积单位 **㎡**，单价 **元/㎡**

## 6. 异动识别引擎

`services/anomaly.py`，纯函数，输入「一条房源 + 它的调价历史 + 市场统计」，输出 0~N 条事件。

| 类型 | 规则 | 可调阈值 |
|---|---|---|
| `sudden_drop` 突发降价 | 单次降幅 ≥5%，或 7 日内连降 ≥2 次 | `SUDDEN_DROP_PCT` |
| `deep_dip` 深跌 | 当前单价低于同小区同户型近 3 月中位 ≥12% | `DEEP_DIP_PCT` |
| `long_listed` 久挂让利 | 挂牌 >180 天 **且** 近 30 天有降价 | `LONG_LISTED_DAYS` |
| `miskill` 错杀候选 | 单价偏低且硬伤**全部**属可改善项（装修旧/北向/采光差…） | — |
| `board_divergence` 板块背离 | 板块横盘/下行，小区与个盘均低于板块中枢 5%+ | — |
| `new_home` 新房倒挂 | 新盘/抵账房/尾盘报价低于周边二手 5% 以上 | — |
| `auction_deal` 法拍机会 | **到手价**净折扣 ≥15% 且占用/税费风险为中低 | `AUCTION_NET_DISCOUNT` |

设计上的三个刻意选择：

1. **板块背离按小区去重**——同一小区当天只报一条，否则整个便宜小区会刷屏。
2. **法拍折扣一律按到手价算**——起拍价好看不等于到手便宜。
3. **事件严重度统一由评分分级决定**，而不是异动幅度：幅度大但风险高的，只进「仅记录」。

## 7. 捡漏评分模型

`services/scoring.py`，0~100 分，纯函数，透明可解释。

```
leak_score =
    价格偏离 30%   低于可比中枢越多越高，>35% 极端偏离压分（防垃圾房）
  + 调价动机 15%   连降/长挂/累计降幅大 = 急售；硬伤甩卖打 0.55 折
  + 硬伤可控 20%   产权/占用/腾退类直接打穿；装修/朝向类轻扣
  + 流动性   15%   板块成交活跃度 + 个盘成交 + 总价接盘面；扩展区额外折扣
  + 自住适配 20%   板块/面积/户型/电梯/房龄/学区，按用户偏好
```

### 校准结果（演示数据集，220 套在挂 + 5 条法拍 + 8 个新盘）

| 统计量 | 数值 |
|---|---|
| 中位分 | 48 |
| 🔴 重点留意 | 3 |
| 🟡 建议观察 | 17 |
| ⚪ 仅记录 | 205 |
| 异动事件（7 类合计） | 102 条：突发降价 56 / 久挂让利 16 / 深跌 11 / 错杀候选 10 / 法拍机会 5 / 板块背离 3 / 新房倒挂 1 |

也就是说：**九成房源会被判成"没什么可看的"**，这是刻意调出来的——正常房源不该在 60 分以上。

### 分级规则（顺序即优先级）

1. **风险高**（产权瑕疵/占用/腾退难/租赁/限购，或 ≥2 个不可逆硬伤）→ 一律 ⚪ 仅记录，**绝不主动推送**
2. `score ≥ 75` 且风险低且置信度非低 → 🔴 重点留意
3. `score ≥ 60` → 🟡 建议观察
4. 其余 → ⚪ 仅记录

**置信度**：同小区同户型样本 ≥5 且字段完整 = 高；≥3 = 中；<3 = 低（低置信度不允许报红，价格分自动向 50 收缩）。

### 每条评分都必须输出

- `why_cheap`：它为什么便宜（**假设**，需用户核验）
- `why_good`：为什么可能是真漏
- `why_trap`：为什么可能是坑

这三段不进分数，但会进推送文案和详情页首屏——**判断权交回给人**。

## 8. 小区地图与小区详情

房价的第一性变量是位置。列表页只有「新市区 / 石臼」这种文字板块，看不出同一个板块里靠海那边和靠铁路那边差多少。所以单独做一屏地图（`frontend/src/views/MapView.vue`）。

`/map` 页面：

- **点位大小 = 该小区在售套数，颜色深浅 = 中位单价**（演示集 6,372 ~ 12,074 元/㎡），带红圈的是有红级房源的小区
- 点一下小区 → 右侧档案卡：中位单价、在售套数、去化月数、最高分房源，卡片上直接进小区详情
- 手机端（375px）**隐藏文字标签**（缩放下会小到读不出来），改为放大点击热区（半径 ×1.35 + 12px 透明命中区）
- 未配置 `AMAP_KEY` 时用**自绘 SVG 示意地图**：按 `cos(lat)` 压缩经度做等距投影、按可见点自适应取景框（不用写死边界，换城市也能用）、标签做 8 方向 × 3 距离的贪心避让（先给板块名占位，避免小区名压住板块名）；配置 Key 后自动切成高德底图

#### 配高德底图（可选，约 5 分钟，免费）

不配也能用，只是底图是自绘示意投影（只有相对方位，无道路水系）。想要真实底图：

| 步骤 | 操作 |
|---|---|
| 1 | 打开 `console.amap.com`，手机号注册登录（**个人开发者即可**，不用企业资质、不用绑卡） |
| 2 | 控制台 → 应用管理 → 我的应用 → **创建新应用**（名称随意，行业选出行/生活） |
| 3 | 该应用右侧 **添加 Key** → 服务平台必须选 **「Web端(JS API)」** → 提交 |
| 4 | 复制生成的 **Key**，以及同页下方的 **安全密钥（jscode）** |
| 5 | 打开本站 `/#/admin` → 口令登录 → 「地图底图配置」两栏粘进去 → 保存 → 回地图页刷新 |

两个坑，代码里都做了兜底：

- **服务平台选错**：选成「Web服务」的 Key 是给后端调 HTTP 接口用的，前端加载会失败并自动回退到示意底图（页面会提示原因）。
- **缺安全密钥**：高德 JS API 2.0 自 2021-12 起强制校验 `jscode`，只填 Key 会白屏报 `INVALID_USER_SCODE`。现在前端在加载前会写入 `window._AMapSecurityConfig`，管理台也单独给了这一栏。

底图是**渐进替换**的：进页面先渲染示意地图，只在真实底图确认起来之后才盖上去（另有 9 秒硬超时）。所以 Key 填错、白名单没加域名、网络卡住，最坏结果也只是继续看示意地图，顶部挂一个「底图加载失败 · 已用示意底图」的标签告诉你原因——不会给一块白板。

配置存 `app_setting` 表，**优先级高于 `.env`**，保存即生效不用重启；也可以用 `.env` 的 `AMAP_KEY` / `AMAP_SECURITY_CODE` 配（改完要重启）。JS API Key 与 jscode 本来就是浏览器端凭据（打开开发者工具就能看到），所以 `/api/config` 会下发它们；企微 Webhook、应用 Secret 这类真密钥不在其中。

小区详情 `/community/:id`（`routers/communities.py`）把六件事摊在一屏上：

| 模块 | 回答的问题 |
|---|---|
| Hero 四个数 | 中位单价 / 中位总价 / 在售套数 / 120-150㎡ 套数 |
| 流动性提示 | **去化月数** = 在售套数 ÷（近 90 天成交 ÷ 3），比人工的「流动性分数」硬 |
| 在售房源表 | 这个小区**所有**在挂房源一表排开，可按单价 / 总价 / 面积 / 挂牌天数 / 捡漏分排序 |
| 同户型竞争格局 | 同户型在挂几套、价差多大 → 直接决定你能砍多少（同户型挂得越多越难卖，议价空间越大） |
| 近期异动 | 按房源聚合（同一套房的 5 条异动合成 1 行，标签去重、取最严等级），避免刷屏 |
| 同板块参照 | 同板块其他小区 + 在售新盘，判断这个价格在当地是什么水平 |

去化月数的分档口径（`liquidity_note()`）：

| 去化月数 | 判读 |
|---|---|
| 无成交 | 近 90 天无成交记录，转手难度大，自住可以、投资要慎重 |
| ≤ 6 | 好卖的小区 |
| 6 ~ 12 | 供需正常 |
| 12 ~ 24 | 卖得偏慢，砍价空间相对大 |
| > 24 | 供给远大于需求，买入后想卖会很难 |

扩展区（莒县 / 五莲 / 岚山）会在结论后追加「属扩展区，二手接盘面更窄，流动性要额外打折」。
注意 `target_area_n` 固定按 `TARGET_AREA_MIN/MAX`（120-150）统计，**不随当前筛选变**——否则「18 套大户」会变成全部在售的误导数字。

### 8.1 搜索小区

顶栏搜索按钮 / 侧边「搜索小区」进入 `SearchView.vue`。一次输入同时查三类结果：

- **小区**：名称、别名、板块、对口学校、以及该小区房源标题；
- **房源** `/api/listings?keyword=`、**新盘** `/api/new-homes?keyword=`（列表取前 8 条）。

所有 `LIKE` 都用 `ESCAPE '\'` 并对 `%` / `_` 转义 —— 否则用户搜一个 `%` 会匹配全库，
这是静默但危险的错。搜到的卡片可以直接点星标关注小区。

### 8.2 关注小区房价波动

小区详情页与搜索结果都能「关注房价波动」（`POST/DELETE /api/communities/{id}/watch`，需管理口令）。关注后：

- 每日管线落一条 `community_price_snapshot`：小区在售中位单价、样本量、120-150㎡ 套数；
- 启动时用 `price_history` + `first_price` **回推周度中位价**，让新库也有历史曲线（标 `data_kind='backfill'`）；
- `GET /api/communities/{id}/trend` 返回 7/30/90 天变化、高低点、波动率与**口径说明**；
- 「观察清单」里小区项显示 **元/㎡** 与价格曲线（不是房源总价），点击跳小区详情；周报不会因它没有捡漏分就误判为「建议剔除」；
- 近 7 天中位价变动超过 2% 时生成推送提醒，文案明确提醒「可能只是房源结构变化」。

回推点是**估算**，只反映发生过调价的样本，不等于当日全量挂牌；页面会把回推点数量直接写出来，不冒充当日快照。

## 9. 新房倒挂判定（双口径）

自住买房最常见的错觉是「新房 1.1 万，旁边二手 1.2 万，新房便宜」。但两者**不可直接比价**：

1. 新房多为毛坯，装修还要另花 1000~1500 元/㎡；
2. 新房得房率通常 75%~80%，二手 80%~85%，同样的「建筑面积」新房实际能用得更少；
3. 新房有交付风险（延期、减配、精装降标），二手是现房。

所以 `routers/newhomes.py` 同时给两个数：

```
名义倒挂    nominal_gap  = 1 - 新房均价 / 周边二手中位
调整后倒挂  adjusted_gap = 1 - (新房均价 + 装修成本)/0.78 ÷ (二手均价/0.82)
```

得房率常量 `NEW_EFFICIENCY=0.78` / `USED_EFFICIENCY=0.82` 与毛坯装修 `NEW_DECOR_COST=1200` 元/㎡ 都在 `config.py`，可调。
**只有调整后仍然倒挂，才认为值得看**；否则就是被建筑面积骗了。

判读门槛（`verdict()` 纯函数，顺序即优先级）：

| 条件 | 结论 | 文案 |
|---|---|---|
| adj ≥ 8% **且无**硬风险 | `opportunity` 真倒挂 | 值得实地看 |
| adj ≥ 5% **但有**交付/配套硬风险 | `caution` 倒挂有风险 | 先查预售资金监管与工程进度 |
| adj ≥ 2% | `slight` 正常差异 | 不作为捡漏理由 |
| adj ≥ -3% | `neutral` 基本持平 | 比的是产品与交付确定性 |
| adj < -3% | `premium` 新房溢价 | 自住喜欢可以买，别当捡漏 |

硬风险标签：`交付风险` / `烂尾` / `教育配套未落地` / `土地年限不足`。

演示集 8 个在售盘的实测结果（`GET /api/new-homes`）：

| 楼盘 | 板块 | 名义倒挂 | 调整后倒挂 | 判读 |
|---|---|---|---|---|
| 兴业·海曲府 | 新市区 | +16.9% | **+12.7%** | 🔵 真倒挂 |
| 高新·智谷佳苑 | 高新区 | +12.8% | **+8.4%** | 🔵 真倒挂 |
| 开发区·奎山壹号 | 开发区 | +29.8% | +7.8% | 🟠 倒挂有风险（教育配套未落地） |
| 石臼·海曲新苑 | 石臼 | +11.0% | +6.4% | 小幅倒挂 |
| 城建·海韵华府 | 东港区 | +6.7% | +1.9% | 基本持平 |
| 山海天·蓝湾 | 山海天 | +10.2% | -7.6% | 新房溢价 |
| 安泰·悦府 | 新市区 | -6.8% | -12.3% | 新房溢价 |
| 华润·置地中心 | 新市区 | -17.0% | -23.0% | 新房溢价 |

> 奎山壹号名义倒挂 29.8% 最夸张，调整后只剩 7.8%，且带「教育配套未落地」——这类正是「看着最便宜、实际最不能买」的典型。

每张卡片还给「起总价 / 月供 / 首付+税费现金门槛」三个数，以及 5 条核验清单：

1. **五证与预售资金监管**：查预售许可证编号，并在住建局网站核对资金监管账户是否正常
2. **交付时间与违约条款**：合同里的交付日期、延期违约金比例，口头承诺不算
3. **得房率与公摊**：问清套内面积与公摊比例，同样 120㎡ 实际可能差 8㎡
4. **精装标准落地**：品牌型号写进合同，样板间与实体交付常有差距
5. **学区是否已落地**：新盘学区未划定前，销售说「规划中」就等于没有

## 10. 改善 120-150㎡ 专题

`/area`（`routers/target.py`）把 120-150㎡ 独立成屏。改善型买家的判断逻辑和刚需不同：**总价高、客群窄、转手慢，但正因为难卖，议价空间最大**。

页面结构：

- 面积段预设：120-150 / 110-130 / 130-160 / 90-120，也可手填（`GET /api/target?min_area=&max_area=`）
- 6 个统计卡（演示集，120-150㎡ 口径）：二手在售 **63** / 法拍 **1** / 在售新盘 **7** / 中位单价 **8,577 元/㎡** / 中位总价 **114.8 万** / 分级 **1 红 7 黄**
- 三条反直觉提示（都是算出来的，不是写出来的文案）：
  1. **大面积单价本来就低** —— 同小区 120-150㎡ 单价平均比小面积低 **3.0%**（12 个小区可比样本）。所以「单价便宜」先别当漏。
  2. **总价高 = 客群窄 = 卖得慢** —— 这个面积段的挂牌天数普遍长于 90㎡ 小户。
  3. **正因难卖，议价空间更大** —— 挂牌天数长、调价次数多，是真正能谈下价格的板块。
- 三个标签页：二手 / 法拍 / 在售新盘。新房按「在售面积段与 120-150 有交集」筛选，不是拿单一面积极值硬套
- 每张二手卡直接给「月供 + 现金门槛」，不用点进去算

`size_premium()` 的口径：逐小区比较「120-150㎡ 中位单价」与「<120㎡ 中位单价」的百分比差，再对可比小区取平均；单边样本不足 3 套的小区不参与。

## 11. 购房成本与议价参考

`services/afford.py` 纯函数，前端 `AffordPanel.vue` 用同一套公式实时联动（拖首付比 / 年限 / 利率立刻重算，不用请求后端）。

### 一次性现金门槛 ≠ 首付

```
cash_needed = 首付
            + 契税（分档）
            + 中介费（默认 2%）
            + 维修基金（90 元/㎡）
            + 毛坯装修（1200 元/㎡，仅毛坯房计入）
```

很多人的真实卡点是这笔钱，不是月供：演示集一套 92 万的毛坯两居，首付 27.6 万，但现金门槛约 33 万。

### 契税分档（`deed_tax()`）

| 情况 | 面积 | 税率 |
|---|---|---|
| 首套 | ≤ 90㎡ | 1% |
| 首套 | > 90㎡ | 1.5% |
| 二套 | ≤ 90㎡ | 1% |
| 二套 | > 90㎡ | 2% |
| 三套及以上 | 任意 | 3% |

### 议价锚点（`bargain_anchor()`）

三个锚，合起来给出「可谈空间」与「建议出价」：

| 锚 | 含义 |
|---|---|
| 同户型中位 | 挂牌价高于同户型中位多少 → 高于中位才有谈的空间 |
| 挂牌天数 + 调价次数 | 挂了 200 天、降过 3 次 → 卖方心态已经松动 |
| 流动性分 | 小区去化慢 → 卖方更急 |

硬约束（防止给出荒唐报价）：

- 建议出价 **≤ 挂牌价 × 0.995**（不能比挂牌还高——上一版真出过 120 万挂牌算出 136 万建议的 bug，已用单测固定住）
- 建议出价 **≥ 挂牌价 × 0.85**（低于 15% 的报价大概率不被理会，只是浪费时间）
- 挂牌价已低于同户型中位 3% 以上时，可谈空间自动 ×0.6（已经便宜的房子没那么多水分）

### 租金视角

`annual_rent / total_price` 给出租金回报率与回本年限。日照演示集约 1.5%~2.5%，明显低于这个区间说明价格相对租金偏高（持有底线要心里有数）。

## 12. 权限模型与管理台

**规则一句话：看是全开放的，改只有你能改。**

`main.py` 的 `admin_guard` 中间件：

| 请求 | 行为 |
|---|---|
| `GET /api/**` | 全部放行（任何人可以看数据） |
| `POST/PUT/PATCH/DELETE /api/**` | 需要 `X-Admin-Token` 请求头，否则 401 + `code: ADMIN_REQUIRED` |
| `POST /api/admin/login` | 白名单（否则没法登录） |

口令来源优先级：

1. `.env` 的 `ADMIN_TOKEN`（显式指定，最高优先）
2. 数据库 `app_setting.admin_token`
3. 都没有 → 首次启动自动生成 16 位口令，写入 `app_setting` + `data/admin_token.txt`，日志打印一次

校验用 `hmac.compare_digest`（常量时间比较，避免时序侧信道）。想彻底关掉鉴权把 `ADMIN_ENABLED=0`。

口令可以设得好记（比如配置里的 `rizhao2026`），但登录接口有一层失败限速兜底：
**同一 IP 5 分钟内错 5 次，锁 5 分钟**（返回 429 + 剩余时间），成功一次即清零。
限速状态存在进程内存里，重启后端即解除；多人共用同一出口 IP 时注意别互相锁到。

前端拿到 401 不会静默失败：`api.js` 派发全局 `authEvents` 事件，`App.vue` 统一提示「需要管理口令」并跳 `/admin`（3 秒防抖，避免一屏多请求刷屏）。

管理台 `/admin` 能做什么：

| 区块 | 内容 |
|---|---|
| 运行状态 | 在挂房源 / 法拍 / 新盘 / 小区 / 已算评分 / 异动事件 / 推送条数 |
| 数据更新机制 | 下次更新时间（秒级倒计时）、每日计算时间、定时任务状态、抓取开关状态 |
| 配置在哪改 | 「可以在管理台改的」与「必须改 `.env` 的」两栏对照 + 数据库与口令文件的绝对路径 |
| 企业微信推送 | Webhook / CorpID / Secret / AgentId / 接收人 五个字段，保存即生效，带「发送测试消息」 |
| 权限与安全 | 三类权限说明 + 口令在哪看 |

密钥处理：**回显只给尾部 6 位**（`••••••••wxkey1`）。前端表单留空表示「不修改」，填内容才覆盖，清空才删除——避免误把 `••••` 存回去。

## 13. 数据更新机制与配置位置

这一节直接回答三个问题：**在哪配置、多久更新、怎么管理**。

### 配置在哪（两处，各有分工）

| 配置项 | 位置 | 要重启吗 | 说明 |
|---|---|---|---|
| 企业微信群机器人 Webhook | **管理台「企业微信推送配置」** | ❌ 不用 | 存 `app_setting`，保存即生效 |
| 企业微信应用消息 / 公众号 / 高德 Key | 管理台（同一张表） | ❌ 不用 | `WECOM_*` / `MP_*` / `AMAP_KEY` |
| 管理口令 `ADMIN_TOKEN` | `.env` 或首次自动生成 | ✅ 要 | 自动生成的口令在 `data/admin_token.txt` |
| 抓取开关 `CRAWL_ENABLED` | `.env` | ✅ 要 | 默认 0，开 1 才会去真实站点 |
| 调度开关 `ENABLE_SCHEDULER` | `.env` | ✅ 要 | 云托管可关掉，改手动触发 |
| 每日计算时间 `DAILY_RUN_AT` | `.env` | ✅ 要 | 默认 `02:30` |
| 抓取间隔 / 阈值 / 评分权重 | `.env` | ✅ 要 | 见 `.env.example` |
| 推送阈值 / 静默时段 / 自住偏好 | 「推送设置」页 | ❌ 不用 | 存 `alert_config` / `user_pref` |

> 一句话记法：**密钥类去管理台填（即时生效），开关类去 `.env` 改（要重启）**。

### 多久更新一次

| 任务 | 频率 | 做什么 |
|---|---|---|
| 每日增量流水线 | 每天 **02:30**（`DAILY_RUN_AT`） | 抓取（若开启）→ 重算统计 → 重算评分 → 跑 7 类异动 → 红黄级推送 |
| 观察周报 | 每周一 **08:30** | 对观察清单做「仍值得看 / 建议剔除 / 新可比低价」三分类 |
| 手动立即更新 | 随时 | 管理台点「立即运行一次」，或 `POST /api/admin/run-now` |

一次增量流水线具体做六件事（`services/pipeline.py`）：

1. `CRAWL_ENABLED=1` 时先跑抓取（去重、调价追踪、异常隔离），否则跳过
2. 重算板块 / 小区 / 同户型的中位单价与成交活跃度
3. 对全部在挂房源重算 `leak_score`（含置信度与三问文案）
4. 跑 7 类异动规则，按 `event_key` 日级去重写入 `anomaly_event`
5. 按分级 + 阈值 + 静默时段 + 24h 去重窗口决定推不推，写 `alert_log`
6. 记录 `crawl_log` 与调度状态，供管理台读取

关于「数据会不会自己长」：**默认 `CRAWL_ENABLED=0`**，每天只是拿已有数据重算一遍（价格不动，异动就不会每天新增）。
要让数据真更新，需要 `CRAWL_ENABLED=1` + 目标站点允许抓取 + 选择器验证通过。管理台会明确写出「当前不会抓取新数据」，不给你一个假的「正在更新」的错觉。

### 怎么管理（三步）

1. 打开 `/admin`
2. 输入口令登录（口令在 `data/admin_token.txt`，或 `.env` 的 `ADMIN_TOKEN`）
3. 在管理台配企业微信、看运行状态、点「立即运行一次」

口令存在浏览器 `localStorage`（键 `rz_admin_token`），随请求放进 `X-Admin-Token` 头；换浏览器 / 清缓存需要重新登录。

### 数据会丢吗：三重保险

把数据分成两类，保护策略完全不同：

| 类别 | 有哪些 | 会不会丢 | 怎么恢复 |
|---|---|---|---|
| **可重建** | 小区、房源、法拍、新盘、评分、异动 | 丢了也没关系 | 重启自动重灌样本 / 重跑增量 |
| **你自己攒的** | 观察清单、自住偏好、推送配置、企微密钥、管理口令 | **丢了就真没了** | 靠下面的三重保险 |

1. **每日自动快照**（`services/backup.py`）
   每天跑增量计算**之前**先 `VACUUM INTO` 一份整库快照到 `data/backups/`，保留最近 14 份。
   用的是 SQLite 官方热备语法，对运行中的库是一致性快照，不会拷到写了一半的 WAL。
   调度器没开时，启动也会补一份当天的。
2. **手动导出 / 导入**
   管理台「数据备份」→ **下载备份文件**，得到一个几十 KB 的 JSON（只含上面「你自己攒的」四张表，
   房源数据不进备份），可以直接发自己微信里存着。换设备、换服务器都能「从备份文件恢复」。
3. **重灌不伤人**
   `seed_all(clear=True)` 清库前会先把用户资产取出来，灌完原样还回去——升级演示样本不再洗掉观察清单。
   观察记录指向的房源靠 `fingerprint`（去重指纹）重新定位，而不是靠自增 id：
   重灌后 id 会变，第一版按 id 恢复时 4 条观察全被当成悬空引用清掉了，
   日志却写着「已还原 4 条」，看着很成功。现在会报「重映射 N，失联 N」，
   真的找不到目标的才丢，并在返回里如实说明。

对应接口：`GET /api/admin/backup`、`GET /api/admin/backup/export`、`POST /api/admin/backup/import`、`POST /api/admin/backup/snapshot`。
注意 **导出接口即使是 GET 也要口令**——那里面有明文口令和企微密钥。

## 15. 数据来源与合规

**默认 `CRAWL_ENABLED=0`**：开箱即用演示数据，不对外发任何请求。

### 15.1 一条硬原则：不为了「显得房源更全」而造数据

库里曾用固定随机种子生成 220 套**演示样本**展示研判逻辑；在用户明确要求「换成真实的」之后，
演示样本已通过「数据来源 → 清除演示样本」一键清除，线上现在只有真实来源的数据。
数据性质用 `source_kind` 标死，前端不许模糊：

| `source_kind` | 含义 | 详情页显示 | 原始链接 |
|---|---|---|---|
| `demo` | 固定种子生成的示意数据 | **演示样本**，平台名一律留空 | 强制为空 |
| `manual` | 人工 / 表格录入，逐条登记 | 人工录入 + 来源名称 | **必填** |
| `crawled` | 采集通道抓取 | 自动采集 + 平台名 + 抓取时间 | 必填 |

`source_info()` 是唯一的序列化出口：演示样本即使 `source` 字段写着 `fangtianxia`，
也只显示「演示样本」，`platform` 与 `url` 一律为空 —— 不会在详情页伪装成「来自房天下」。
`/api/config` 的 `demo_only` 会如实告诉前端「当前是否全是演示数据」。

### 15.2 来源目录：写了解析器 ≠ 接上了数据

`services/sources.py` 的 `SOURCE_REGISTRY` 列出全部通道，`GET /api/sources` 公开可查，
每个通道的**真实条数、验证状态、最近采集时间**逐项如实展示：

| 通道 | 类型 | 状态 |
|---|---|---|
| **贝壳找房 · 日照二手房** | 二手挂牌 | ✅ **已验证**：2026-11 实抓全站在售 149 套（去重后 145 套入库），含原始链接、真实坐标 |
| **安居客 · 日照二手房** | 二手挂牌 | ✅ **已验证**：PC 站是 JS 验证壳，但移动站 `m.anjuke.com/rz/sale/` 可解析；实抓 175 套（去重后 171 套入库），含区/板块 |
| **58同城 · 日照二手房** | 二手挂牌 | ✅ **已验证**：复用你在浏览器里正常访问后的会话，服务端低频抓 SSR 列表页首屏；2026-11-06 实抓 117 套。连续翻页会触发 antibot，因此只抓一页、每天两次；不破解验证码 |
| 房天下 · 日照二手房 | 二手挂牌 | ❌ 当前网络无法连通（代理 502） |

### 15.2.1 每天自动更新两次（07:30 / 19:30）

服务端调度器每天两次执行「抓取 → 入库 → 记调价 → 重算评分」：

```
live_refresh_0 / live_refresh_1  →  live_refresh.refresh_all()
    ├─ 贝壳  : 抓列表页 5 页（≥4s 间隔）
    ├─ 安居客: 抓移动站 3 页（≥6s 间隔，风控更敏感）
    ├─ 58同城: 复用已同步会话，只抓首屏 1 页（≥8s 间隔）
    ├─ 入库  : 按平台房源编号匹配（价格变了还是同一套房）→ 更新价格 + 写 price_history
    └─ 重算  : run_daily_pipeline(push=True) → 评分/异动/推送
```

- 时间可配：`.env` 的 `REFRESH_AT=07:30,19:30`；页数 `REFRESH_PAGES`；关闭 `LIVE_REFRESH_ENABLED=0`
- 线上托管环境已验证可出网（`GET /api/admin/net-check` 可自检）
- 手动触发：管理台「数据来源 → 立即刷新房源」（异步执行，前端轮询 `GET /api/admin/refresh-status`；
  因为网关 60s 超时，一次完整刷新约 50~120s，必须异步）
- 单源失败/被验证码拦住只记录，不影响其它源，也不会让站点停在旧数据
- 58 只抓首屏的原因：此前扩展每 2 小时后台开一次列表页，被判定「访问过于频繁」，
  验证码弹在用户看不见的后台标签里，会话反而失效。改为服务端低频抓一页后不再复现

**关键改动：按平台房源编号去重**。原先指纹含总价，价格一变动就会多出一条「新房源」，越抓越重复。
现在优先用 `source_ref`（贝壳 houseId / 安居客 pid / 58 esfId）判定同一套房：价格没变就只更新挂牌天数，
价格变了更新价格并追加一条 `price_history`（前端时间轴、深跌/连降异动都依赖这条链）。
早期没有编号的老记录，第一次刷新时会按指纹命中并自动补上编号（自愈迁移）。

### 15.2.2 免验证码的全自动通道（实测）

| 通道 | 是否要验证码 | 代价 / 局限 |
|---|---|---|
| **日照房管业务网公开 JSON 接口**（`www.rzfcfw.cn/second/phase/queyrHtqygs`、`queyrEsfbaInfo`） | **不要，全自动** | 政府公开的二手房签约/备案公示（实测 841 条）。**价格字段为空、数据停更于 2023 年**，只能做核验参考，不能更新挂牌价。`GET /api/admin/official-deals` 可随时实测 |
| 58 开放平台 `open.58.com` 的房产服务 API（AppKey + 签名） | 不要，全自动 | **需企业资质与商务授权**，个人拿不到 |
| 第三方数据服务（如 Apify 58 二手房 Scraper） | 不要，全自动 | 按量付费（约 $8/千条）、需账号，且是第三方抓取 |
| 贝壳 / 安居客现有通道 | 通常不要 | 已在跑；安居客翻页过快会临时弹极验，已降到每次 3 页 + 6s 间隔 |

**结论（2026-11-06 更新）**：58 网页端不需要「识别验证码」也能全自动 ——
把你正常访问后的会话交给服务端、低频抓 SSR 首屏即可。实测服务端带会话请求返回 1.42 MB
完整列表页、解析出 117 套房源，全程无验证码。风控只在「短时间连续访问/翻页」时出现，
所以刻意只抓一页、每天两次。商业渠道仍可作长期备份方案。

### 15.2.3 会话复用：服务端全自动抓取与推送

`tools/bridge-extension/` 是一个 Chrome 扩展（**本机已装好并配置完**，桌面快捷方式「日照房价探针」）：

1. 你在 58 网页上正常打开列表页（首屏通常不弹验证码；真弹了由你本人完成，程序不识别、不破解）；
2. 扩展监听 Cookie 变化，自动把会话同步到 `PUT /api/admin/sources/wuba/cookies`（每 30 分钟保鲜）；
3. 内容脚本按卡片 class 精确读取**你已经看到的**房源 DOM，回传到 `/api/admin/sources/import`
   （`source_key=wuba`，每条带干净的原始链接与 `source_ref`，后端逐行校验）；
4. 回传后自动触发 `/api/admin/refresh-sources`（异步重算），
   `push_refresh_summary()` 把「本次新增 / 调价 / 黄级线索」**主动推送**到企微或站内提醒；
5. 此后每天 07:30 / 19:30 **服务端**复用这份会话自动抓 58 首屏 + 贝壳 + 安居客，
   解析入库、记调价、重算并推送。扩展不再定时后台开页面（那会触发「访问过于频繁」验证）。
   会话失效时刷新摘要会如实提示「请在网页端打开一次页面」。

解析器 `parse_wuba()` 按卡片 class 精确取字段，并做「总价÷面积 ≈ 页面单价」交叉校验，
对不上的行直接丢弃；单测 `backend/tests/test_wuba_parser.py` 覆盖错价、缺字段、跨卡片串价等场景。

页面「数据来源 → 全自动接入」里可一键 `检查会话状态` / `实测取一次政府接口`。
管理接口：`GET /api/admin/sources/cookies`、`GET /api/admin/sources/session-check?key=wuba`。

### 15.2.4 验证码：人工过一次，会话交给程序

58 同城弹人工滑块、安居客翻页多了会弹极验。**本系统不识别、不破解任何验证码**
（既违反站点技术保护，也违反 `crawler/base.py` 的合规红线）。合法且稳定的做法是：


### 15.2.5 真实成交价：日照的实测结论与替代方案

**实测结论（2026-11-07）：日照这个城市在主流平台上没有公开的成交记录页。**

| 尝试 | 结果 |
|---|---|
| 贝壳成交页 rz.ke.com/chengjiao/ | 会被重定向回二手房列表（ljConf.channel=ershoufang），无成交数据 |
| 安居客成交页 m.anjuke.com/rz/chengjiao/ | 直接 404 |
| 贝壳小区行情页「参考均价」 | 空值（小城市无成交样本） |

既然拿不到「真成交价」，系统改用三条**能稳定全自动拿到、且口径诚实**的数据逼近真实：

1. **下架追踪（成交活跃度代理）**：每套房上次还在、连续 ≥10 天不再出现 → 标记 delisted。
   只有「当天确实抓过该来源」才判定，避免把「没翻到那一页」误报成下架。
   **下架 ≠ 成交**（也可能是中介撤牌），所以它只用来判断活跃度方向和近似去化速度，不当成交套数。
   services/market_pulse.py · detect_delistings()，每次刷新后自动执行。
2. **全城日快照**：在售总量 / 中位挂牌单价 / 当日新增 / 当日下架，落 market_daily 时间序列
   （只统计 source_kind='crawled'，演示样本不计入）。前端首页「市场大盘」卡片 + GET /api/market/overview。
3. **法拍成交结果回填（真实价格锚点）**：法拍是日照少数能公开拿到真实成交价的渠道。
   拍卖结束后 POST /api/admin/auctions/{id}/result 录入成交价，写回 deal_price 并生成 auction_result 事件。

去化近似 = 在售总量 / 近 30 天下架量，明确标注为「近似」，只做方向参考。
小区的「近 90 天成交套数」community.deal_active_90d 也会由下架量自动回填（有真实采集数据时）。

### 15.3 让房源真正变全：导入真实挂牌

「数据来源」页提供 JSON 导入（需管理口令），这是目前唯一能保证准确和真实的路径：

```json
[
  {
    "community_name": "某某花园", "district": "东港区", "layout": "3室2厅",
    "area": 128.5, "total_wan": 112,
    "source_url": "https://example.com/house/123456",
    "source_ref": "123456", "list_days": 45, "floor_text": "8/18层"
  }
]
```

字段模板见 `GET /api/sources/template`。校验规则写死在 `import_listings()`：

- `community_name` / `area` / `total_wan`（或 `total_price`）/ `source_url` 缺一不可；
  **没有原始链接的行直接拒绝** —— 没有链接就无法回溯核验；
- 面积 20~600㎡、总价 10 万~1 亿，明显填错的数值挡在门外；
- 同小区 + 同户型 + 同面积 + 同总价按指纹去重；
- 小区名先精确匹配、再包含匹配，都没有才按填写的板块新建（不静默丢弃）；
- 单批最多 500 条；每次导入写 `source_import_batch` 批次，可逐批回溯；
- 导入后须点一次「重算」，新房源才参与评分与异动检测。

**一旦库里出现真实房源，`bootstrap()` 会禁止重灌演示数据**，避免把用户录入的东西洗掉。

### 15.4 合规红线（写死在 `crawler/base.py`，不是文档约定）

- 单站请求间隔 **≥3 秒**（`CRAWL_MIN_INTERVAL`）
- 先读 **robots.txt**，`Disallow` 的路径直接放弃
- **不登录、不带 Cookie、不破解验证码、不碰联系方式等隐私字段**
- 遇到 403/429 立刻停止该站点（`fetcher.blocked = True`）
- **异常隔离**：单站失败只写 `crawl_log`，不影响其他站点与整体流程
- 只抓公开列表页的公开字段

已实现的解析器（站点改版时只需改选择器，多候选兜底）：

| 文件 | 站点 | 说明 |
|---|---|---|
| `crawler/secondhand.py` | 房天下日照 / 安居客日照 / 日照房产网 | 列表页解析 → 字段清洗 → 指纹去重 |
| `crawler/auction.py` | 阿里资产 / 京东资产 司法拍卖 | 公告解析 + 到手价估算（税率 4.5%、欠费 15 元/㎡、维修 400 元/㎡ 兜底） |

> ⚠️ 站点 DOM 会变，首次真正接入前请先用小流量验证选择器；`auction` 的三项兜底值应改为人工核对后回填。

### 15.5 数据口径声明

- **挂牌价 ≠ 成交价**：所有「低于中枢」都是相对**在挂房源中位**，不是真实成交中位。若有历史成交字段，应优先用它——`price_history.kind = 'deal'` 已预留。
- 小区波动跟踪的是**在售中位挂牌单价**，不是成交价，也不是同一套房的降价；新挂高价房、低价房成交下架都会让中位价变动（结构性变化）。
- **租金回报** 为挂牌中位 × 12 / 总价，仅作持有底线参考。
- **法拍到手价** 为估算，真实税费以当地税务与法院公告为准。
- **下架 ≠ 成交**：market_daily.delist_n 是把「多日不再出现」当作成交活跃度的保守代理，含中介撤牌等情况；去化月数是用它做的近似，只能看方向，不能当成交套数。
- **市场大盘只统计真实采集房源**（source_kind='crawled'），演示样本不计入。

## 18. 已知限制

1. **线上数据 = 贝壳 + 安居客双源真实在售**：316 套（贝壳 145 + 安居客 171），每条带原始页面链接可回溯；198 个小区，其中 99 个有贝壳真实坐标（安居客新增小区暂无坐标 → 地图不显示，列表/搜索/详情正常）。但**仅二手**：法拍（需 JS 渲染）、新盘（CAPTCHA）、58 同城（人工滑块验证码）、房天下 / 日照房产网（不可达）当前均无法接入，对应页面为空是真实状态；部分小区的建成年 / 电梯 / 去化成交数暂缺，会随数据源补充逐步完善。
   演示样本已被清除且不再重灌（`seed_version=purged-demo`）；管理台「数据来源 → 清除演示样本」可随时重复此操作。
   演示模式（`CRAWL_ENABLED=0`）且库里**没有任何真实房源**时，若 `SEED_VERSION` 与库里记录不一致，启动会清空重灌一次演示数据；
   资产（观察清单 / 偏好 / 推送配置 / 运行期设置）会先备份再还原，不会丢。一旦导入过真实房源，重灌被禁止。
5 个采集通道的 `verified=False` 是实情：解析器代码存在，但选择器尚未在真实站点逐项验证，不能当作已接通的数据源。其中 58 同城会弹人工滑块验证码，按 `crawler/base.py` 的合规红线**不破解验证码**，因此不提供自动采集。
2. **"近 3 月中位"用的是在挂房源**，不是成交价。真实成交数据需要额外的数据源；表结构已预留 `price_history.kind='deal'`。
3. **流动性分数（`liquidity_score`）目前是人工先验**（按板块 + 成交活跃度），小区页更硬的「去化月数」依赖 `community.deal_active_90d`，演示集同样是示意值。真正可用需要成交数据源。
4. **地图默认不加载底图**：未配置 `AMAP_KEY` 时用自绘 SVG 示意投影（**只表达相对方位与距离，没有真实道路/水系**，不用于任何行政边界表达）；配置后使用高德地图（GCJ-02）。代码中不含任何内置密钥。
5. **法拍税费/欠费/维修为兜底估算**，竞拍前必须人工核对。
6. **得房率是全市统一常数**（新盘 0.78 / 二手 0.82），没有按楼盘、楼层、是否电梯房细分；新房「调整后倒挂」只用于同量级比较，精确到楼盘仍需查实际套内面积。
7. **契税 / 中介费 / 维修基金按当地常见口径**（首套 90㎡ 分界、中介 2%、维修 90 元/㎡），区县间可能不同，最终以税务与开发商/中介报价为准。
8. **管理口令默认自动生成并明文存于 `data/admin_token.txt`**：单机自用够用；云托管请改用 `.env` 的 `ADMIN_TOKEN` 环境变量，并确保该文件不随镜像分发。
9. 前端首屏 JS 较大（Element Plus + ECharts 全量），生产环境建议按需引入或改 CDN。

## 开源说明

### 本仓库不包含什么

为安全起见，以下内容一律不入库（规则见 `.gitignore`）：

- `.env`、管理口令（`data/admin_token.txt`）
- 任何会话 Cookie（例如 `data/wuba_cookies.json`）
- SQLite 数据库与备份、抓取缓存、Chrome 调试 profile
- 线上部署地址、分享码、webhook 与第三方 API Key

首次启动会用一份演示样本初始化数据库；接入自己的数据源前，请先按 `.env.example`
配置 `.env`。文中部分章节记录的是开发过程中的历史状态，当前能力以最新代码和
`/api/sources` 接口返回为准。

> `tools/bridge-extension/` 里的示例站点域名是占位用途，部署到自己的环境后
> 请按该目录的 README 修改 `manifest.json` 的 `host_permissions` 与配置页参数。

### 数据来源与合规

- 房源来自公开挂牌页面与政府公示接口，只读取列表页已渲染的公开字段。
- **不识别、不破解、不绕过任何验证码**；遇到平台验证，请由使用者本人在浏览器完成。
- 不采集经纪人姓名、电话等个人隐私字段；抓取保持低频与礼貌间隔。
- 使用抓取能力前，请自行确认并遵守目标网站的服务条款与 robots 约定；
  平台调整页面结构或风控策略后，解析器可能失效。
- 数据仅供研究参考，不构成投资、购房或法律建议。

### 运行

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
copy .env.example .env        # macOS / Linux 用 cp
python run.py                 # 默认 8000，浏览器打开 http://127.0.0.1:8000
```

仓库已包含构建好的前端产物（`backend/app/webui`），不装 Node 也能单端口直接跑。
